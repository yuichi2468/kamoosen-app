# 鴨王戦 予選レート戦アプリ 設置手順

対戦の記録はスマホのアプリ画面で行い、データは Google スプレッドシートで管理します。
アプリ画面は Google Apps Script から配信するので、別のサーバーは要りません。

## 入っているファイル

| ファイル | 中身 |
|---|---|
| `Code.gs` | Apps Script 本体（レート計算、記録の受付、シートの読み書き） |
| `index.html` | アプリ画面 |
| `appsscript.json` | Apps Script の設定（タイムゾーン: 日本） |
| `players_template.csv` | 選手一覧の入力例 |
| `engine.js` | 1投ごとの点数計算（Code.gs と index.html に埋め込み済み。設置には不要） |
| `test/` | 動作確認用のテスト（設置には不要） |

## 1. スプレッドシートを用意する（5分）

1. Google ドライブで新しいスプレッドシートを作り、名前を「鴨王戦 予選」などにします。
2. メニューの **拡張機能 > Apps Script** を開きます。
3. 最初からある `コード.gs` の中身を全部消して、`Code.gs` の中身を貼り付けて保存します。
4. 左の「ファイル」の **＋ > HTML** で `index` という名前のファイルを作り（`.html` は自動で付きます）、`index.html` の中身を貼り付けて保存します。
5. （任意）左の歯車「プロジェクトの設定」で「appsscript.json をエディタで表示する」をオンにし、`appsscript.json` の中身に置き換えます。少なくともタイムゾーンが「(GMT+09:00) 東京」になっていることを確認してください。
6. 上の関数選択で **setup** を選んで「実行」します。初回は Google の権限確認が出るので許可してください（「このアプリは確認されていません」が出たら「詳細 > 安全ではないページに移動」）。
7. スプレッドシートに戻ると `players` `matches` `settings` `ranking` `bonus` `log` `throws` `player_stats` `awards` `extra_bonus` の10枚のシートができています。次回からはスプレッドシートを開くと上部に「鴨王戦」メニューが出ます。

### すでに前の版を設置している場合（アップデート）

1. Apps Script のファイルを新しい中身に貼り替えて保存します。**`Code.gs.txt` の中身は「コード.gs」（Code.gs）へ、`index.html.txt` の中身は「index.html」へ**貼ります。逆に貼ると構文エラーになります。
2. 関数 **setup** をもう一度実行します。既存のデータはそのままで、足りないシート（`throws` `player_stats` `awards` `extra_bonus`）、matches シートの新しい列、players シートの `rookie` 列、settings の新しい項目（`awards_visible` `memorial_step` `bonus_wins_step` `bonus_wins_pt` `bonus_partner_tiers` `bonus_opponent_tiers` `bonus_rookie_pt`）、extra_bonus シートの `rookie_pt` 列が追加されます。日程タブを使うには、この setup で `schedule` シートと settings の `sched_day_start` `sched_day_end` `sched_places` が追加されている必要があります（setup を実行しなくても、最初に誰かが参加したときに `schedule` シートは自動で作られます。設定の行は setup で追加されます。追加しない場合は初期値〈7〜20時台、高原・鴨川南・飛鳥井〉で動きます）。
3. 「デプロイ > デプロイを管理 > 編集 > 新バージョン」で更新します。

## 2. 設定と選手を入力する

### settings シート

| key | 初期値 | 説明 |
|---|---|---|
| start_at | 2026/11/24 7:00 | この時刻より前は試合開始できない |
| end_at | 2026/12/07 21:00 | この時刻以降は試合開始できない |
| result_deadline | 2026/12/07 23:59 | 結果入力の締切 |
| min_gain / min_loss | 10 / 10 | 勝ち最低+10、負け最低−10 |
| max_team_size | 4 | 1チームの最大人数 |
| max_singles_vs_same | 3 | 同じ相手との1vs1の上限（Aも対象） |
| min_matches / min_team_matches | 15 / 5 | 参加条件 |
| qualify_count | 8 | 通過人数 |
| admin_key | change-me | **運営画面のパスワード。必ず変更してください** |
| awards_visible | TRUE | 特別賞をアプリに表示するか。FALSE にすると隠れます（awards シートには常に出ます） |
| memorial_step | 100 | メモリアル賞の区切り（100戦目・200戦目…） |
| bonus_wins_step / bonus_wins_pt | 10 / 10 | 追加ボーナス: 10勝ごとに +10pt（到達した区分のみ） |
| bonus_partner_tiers | 5:5,10:15,20:30,30:45,all:100 | 追加ボーナス: チーム戦で組んだ人数の区分（人数:ポイント、all は全員） |
| bonus_opponent_tiers | 5:5,10:15,20:35,30:55,all:100 | 追加ボーナス: 個人戦で戦った相手の人数の区分 |
| bonus_rookie_pt | 30 | ハンデボーナス: 1回生（players の rookie 列）に予選終了後に加算するレート。0 でなし |
| sched_visible | TRUE | 日程タブをアプリに表示するか。FALSE で非表示（運営画面の「表示の設定」からも切り替えられます。非表示のあいだは参加の登録もできません） |
| sched_day_start / sched_day_end | 7 / 20 | 日程: 時間割の時間帯（7時台〜20時台）。期間は start_at〜end_at の日付 |
| sched_places | 高原,鴨川南,飛鳥井 | 日程: 希望場所の選択肢（カンマ区切り）。「どこでも」「その他（自由入力）」は必ず出ます |

レート式の係数（win_base 24、win_coef 0.06、loss_base 20、loss_coef 0.05）も settings にあります。

### players シート

`players_template.csv` と同じ並びで1人1行入力します。

- `player_id`: 重複しない ID（P01, P02 … など）。後から変えないでください。
- `name`: 画面に出る名前。
- `initial_rating`: 初期レート。**空欄は1500**。前回参加者は 1500＋(前回最終−1500)/4（1500未満なら1500）を計算して入力します。
- `fixed_rating`: 前回王者Aの行だけ **1800**。この人はレートが変わらず、順位表にも出ません。
- `active`: 参加中なら TRUE。途中辞退は FALSE にすると選べなくなります（記録は残ります）。
- `rookie`: 1回生なら TRUE（ルーキー賞の対象）。それ以外は空欄。

入力したら「鴨王戦 > レート再計算」を押すと ranking シートが更新されます。

## 3. アプリを公開する

1. Apps Script の画面右上の **デプロイ > 新しいデプロイ** を開きます。
2. 種類の歯車で「ウェブアプリ」を選びます。
3. 「次のユーザーとして実行」は **自分**、「アクセスできるユーザー」は **全員** にしてデプロイします。
4. 表示されたウェブアプリの URL（`https://script.google.com/macros/s/…/exec`）を参加者に配ります。スマホのホーム画面に追加してもらうと便利です。

コードを直したときは **デプロイ > デプロイを管理 > 編集（鉛筆）> バージョン: 新バージョン** で更新すると、URL を変えずに反映できます。

### 注意書きの出ない画面（GitHub Pages）で配る

GAS の URL で開くと、画面の上に「このアプリケーションは Google Apps Script のユーザーによって作成されたものです」と毎回表示されます。これを出さないため、画面（index.html）は GitHub Pages から配り、GAS はデータのやり取りだけに使えます。main に変更が入るたびに、GitHub Actions がテスト → GAS に反映 → 画面を GitHub Pages に公開、まで自動で行います（GAS の URL は画面の中に自動で書き込まれます）。

最初に一度だけ、GitHub で次の設定をします。

1. 無料プランの場合、GitHub Pages はリポジトリが公開（Public）でないと使えません。**Settings > General > 一番下の Danger Zone > Change visibility** で Public にします（運営パスワード `admin_key` はスプレッドシート側にあるので、公開しても漏れません）。
2. **Settings > Pages > Build and deployment > Source** を **GitHub Actions** にします。
3. **Actions** 画面の「GASへ反映・画面を公開」を開き、「Run workflow」で一度実行します。終わると `https://<GitHubのユーザー名>.github.io/<リポジトリ名>/` で画面が開けます。この URL を参加者に配ります。

### 観戦用リンク（参加していない人向け・見るだけ）

`https://<GitHubのユーザー名>.github.io/<リポジトリ名>/watch/` は、鴨王戦に参加していない人向けの見るだけのページです。公開のときに自動で作られます。

- 見られるのは「ランキング／試合／個人／特別賞／ルール」。「試合」タブは上に試合中の試合（タップするとスコア表が約5秒ごとに更新）、その下に対戦履歴です。「ルール」タブは参加していない人向けのルールの概要で、数字は settings シートの値から出します。
- 「試合」「日程」タブと「運営」ボタンはありません。試合の開始・記録・取り消し・日程の登録はできません。
- 参加者用の URL を参加者以外に広めずに済むよう、参加者以外にはこちらを配ってください（参加者用の URL はもともと誰でも開けるので、書き込みを完全に止める仕組みではありません）。

GitHub Actions の Secrets に `GAS_DEPLOYMENT_ID` が入っていることが前提です（画面がこの ID からデータの取得先を決めます）。古い GAS の URL もそのまま使えますが、試合中の記録はスマホの中に URL ごとに保存されるので、切り替えは試合をしていないときにしてください。

## 4. 当日の使い方

**参加者**

1. アプリを開くとすぐ使えます。名前の選択や PIN の入力はありません。
2. 「試合」タブで名前の横の **1** / **2** を押してチームを組み、「試合開始」。開始時刻はサーバーの時計で記録されます。
3. 記録は **1投ごとに記録** が基本です（下の「1投ごとの記録」を参照）。
   - 予備として **結果だけ入力** もあります。スマホの電池切れや記録係がいないときだけ、「試合開始」の下の小さなリンク「予備: 結果だけ入力で始める」を押してから開始します。試合後に同じタブで両チームのセット数（2セット先取）と、任意で得点合計を入れて「結果を確定」。その試合が終わると、次の試合はまた1投ごとの記録に戻ります。
4. ランキング、履歴、個人（選手を選ぶとレート推移・予選通過の最低条件〈最低20試合・うちチーム戦最低5試合〉の進み具合と残り試合数・1vs1の回数）はいつでも見られます。ランキングの「12/15」は「12試合／最低15試合」の意味で、足りないときは赤で表示します。

**1投ごとの記録**

1. 試合開始の画面で、大きな「チーム1 が先攻」「チーム2 が先攻」ボタンで1セット目の先攻（じゃんけんの勝ち）を選びます。
2. 個人戦（1対1）は、個人の投擲成績を必ず記録します。チーム戦で個人の成績も残したいときは「個人の投擲順を入れる」にチェックします。チームに入れた順が1セット目の投擲順で、↑で入れ替えられます。
3. 「試合開始」を押すとスコア入力画面が開きます。投げるたびに、取った点数（1〜12）を選んで「確定」を押します。1本も倒れなければ点数を選ばずに「確定（ミス）」を押します（ミス1回）。
4. 得点、50点ちょうどの上がり、50点超えのバースト（25点に戻る）、3回連続ミスで失格（失格したチームは0点、相手は50点）、次に投げるチーム（と人）はアプリが自動で判定します。間違えたら「1投戻す」。
5. セットが終わると次のセットの準備画面になります。2セット目は1セット目の後攻チームが先攻です。1-1のときは総得点を表示するので、大きな「チーム1 が先攻」「チーム2 が先攻」ボタンで3セット目の先攻を選びます。投擲順を入れた試合では、ここで投擲順を選び直せます（そのままでよければ「この順で始める」）。
6. 2セット先取が決まったら「この結果で確定」を押すと、結果が登録されレートに反映されます。送信中は画面の上に「完了するまでアプリを閉じないでください」と表示されるので、消えるまで待ってください（結果だけ入力の「結果を確定」、「試合開始」を押した後も同じです）。
7. 記録は数秒ごとに自動で保存されます。電波が悪くても入力は続けられ、つながったときに送られます。画面を閉じても「試合」タブの「スコア入力を開く」から続きを入力できます。
8. 1台の端末だけが記録できます。電池切れなどで交代するときは、別の端末で「この端末で記録を引き継ぐ」を押します。ほかの人のスマホでは、「試合」タブで試合中の試合をタップすると観戦画面になり、スコア表が約5秒ごとに自動で更新されます（見るだけで、記録している端末には影響しません）。引き継ぎ・取り消しのボタンは、観戦画面の下の「この試合の操作」にあります。
9. 途中で記録を続けられなくなったときは、予備として「試合」タブの「予備: 結果だけ入力に切り替える」でセット数を入れて確定できます（その場合、途中までの投擲は個人成績に入りません）。

個人タブは、上から「名前・順位・レートのカード」「数字のタイル（試合数・勝利・敗北・勝率・1セット平均・最長連勝・追加ボーナスなど）」「セット内訳（2-0勝・2-1勝・1-2敗・0-2敗）」「最低条件」「直近の試合10件」の順で、レート推移・投擲成績・個人戦の成績・追加ボーナス・1vs1の対戦回数は見出しを押すと開く折りたたみです。成績には、勝率（個人戦・チーム戦・総合）、1セットあたりの平均得点、最長連勝数（と現在の連勝）が出ます。追加ボーナスの「組んだ人数」「戦った相手」の行をタップすると、名前（回数つき）と、まだ組んでいない／戦っていない人が見られます。投擲成績（ヒット率・投擲数・上がり回数。バースト回数はシートにだけ残ります）は、個人の投擲順を入れて（個人戦は必ず記録）最後まで1投ごとに記録した試合だけを集計し、個人ページと `player_stats` シート（投擲数・合計点・ミス数・ヒット率・上がり・バースト）に出ます。ヒット率は「ミス以外の投擲 ÷ 投擲数」です。古い形（平均点・ミス率の列）の `player_stats` シートは、次に結果が登録されたとき、または右上の「運営」ボタンの「レート再計算」を押したときに自動で新しい形に置き換わります。全投擲は `throws` シートに残ります。

**日程（いつ対戦できるか）**

1. 「日程」タブを開き、最初に自分の名前を選びます（端末に覚えておきます）。
2. 時間割（スマホは3日分、広い画面は7日分。‹ › で日をずらす）の数字は、その1時間に「対戦できる」と参加している人数です。濃い緑は2人以上、太い枠は自分が参加している時間、灰色は過ぎた時間です。いまの時間に試合中の人がいると「試合中1」のように出ます。
3. 最初は「時間を選んで参加」です。参加できる時間のマスをタップして選び（もう一度タップで外す。スマホは長押ししてからなぞると続けて選べ、指を離すと少し間を空けて登録画面が出ます）、下の「参加登録」で希望場所・形式・ひとことを入れてまとめて登録します。選んだ時間の「参加をやめる」もあります。
   「参加者を見る」に切り替えると、マスのタップで参加者の一覧（希望場所・希望形式・ひとことは指定のある人だけ）が出て、自分の参加の「編集」「参加をやめる」ができます。
4. 「まとめて追加」で、日（平日・土日・すべて、または日ごと）× 時間帯にまとめて参加できます。参加済みの時間は飛ばします（チェックで上書き）。
5. 自分が参加している時間に、前回閉じたあとでほかの人が新しく参加すると「新着 N件」とマスの黒い点が出ます。マスを開くと消えます。
6. 2人以上いるマスの「このメンバーで試合を始める」で、試合タブに移ります（2人なら1vs1でそのまま入り、3人以上なら選手選びで参加者が上に出ます）。
7. 参加は `schedule` シートに1人1時間1行で残ります（`log` シートに操作した端末の記号も残ります）。ログインがないので他の人の参加も編集できます。おかしな行は運営がシートで消してかまいません。

**運営**

- 記録する人を特定しないので、誰でも試合の開始・結果入力・開始の取り消しができます。誤入力やいたずらへの対策は次のとおりです。
  - どの端末から操作したかを、端末ごとのランダムな記号（例: `端末k3x9qa`）で `log` シートに日時つきで残します。個人は特定しません。
  - 結果はすぐ履歴とランキングに出るので、参加者自身が間違いに気づけます。
  - おかしな記録は右上の「運営」ボタンで無効化・復元できます。
- 右上の「運営」ボタンで admin_key を入れると、試合の無効化・復元と再計算ができます。
- スプレッドシートを直接直してもかまいません（例: matches のセット数・勝者の修正、status を `void` にして無効化）。直したら「鴨王戦 > レート再計算」を押します。
- レートはシートに保存せず、毎回 matches の全試合から開始時刻順に計算し直します。`ranking` シートと matches の `delta_team1/2` 列は確認用の出力なので、手で書き換えても次の再計算で上書きされます。
- 運営判断でボーナスを付ける場合は `bonus` シートに player_id・点数・理由を書いて再計算します（今回の予選では通常は使いません）。

## 5. ルールの実装内容

- 2チーム対戦、各チーム1〜4人。チームの平均レートで計算し、全員に同じ値を反映（人数補正なし）。
- 勝ち: 24＋(相手平均−自分平均)×0.06、負け: 20＋(自分平均−相手平均)×0.05 を四捨五入。勝ちは最低+10、負けは最低−10。
- Aのレートは1800固定。Aとの試合も通常どおり計算する。Aが1人のチーム（1vs1・1人vs複数）はAを1800、Aがほかの人と組んだチームはAを参考レートとして平均（設計書 25.2）。
- 同じ相手との1vs1は3試合まで（Aも対象。無効にした試合は数えない。チーム戦は対象外）。
- 試合中の人は別の試合を始められない。end_at 以降は開始不可、それまでに始めた試合は result_deadline まで結果入力できる。
- 1投ごとの記録: 得点は1〜12の点数を選んで確定。取ったセット数は☆で表示。50点ちょうどでセットを取り、超えたらバーストで25点。チームで3回連続ミスで失格し、失格したチームは0点、相手が50点でセットを取る。2セット目は1セット目の後攻が先攻、3セット目は総得点の高いチームが先攻を選ぶ（同点はドローショット）。総得点は各セットの終了時の得点の合計。
- 特別賞（「特別賞」タブと awards シート。各賞3位まで、同じ値は同じ順位、王者は対象外、無効試合は数えない。チーム戦の結果はメンバー全員に数える）:
  - MVP賞: 勝率／連勝王: 最長連勝数（横綱賞は廃止）
  - 最低条件のある賞（MVP賞・平均得点王・ルーキー賞）は、満たした人を先に並べ、未達の人も「暫定」として表示
  - ジャイキリ賞・カモネギ賞: 格上（チームは平均レート）に勝った・負けた試合の最大レート差。試合当時の両者のレートも表示。王者との試合は数えない
  - 平均得点王: 1セットあたりの平均得点（チーム戦はチームの得点、3ミス失格のセットは0点、得点が記録された試合だけ）
  - ルーキー賞: rookie の人を予選順位順（最低条件を満たした人が先）／ジェットコースター賞: 予選中の最高レート−最低レート
  - メモリアル賞: 大会全体の通算100戦目・200戦目…の試合の勝者
  - 社交王: チーム戦で組んだ人数／開拓王: 個人戦で戦った相手の人数（同じ人は1人、王者も数える）
- 追加ボーナス（extra_bonus シートと個人ページ）: 勝利数・チーム戦で組んだ人数・個人戦で戦った相手の人数の、到達した区分のポイントを合計。予選中も「見込み」としてランキングの合計に入れて順位を出し、結果入力の締切（result_deadline）で確定する。予選通過もボーナス込みの合計で決まる。「全員」は参加中の自分以外の全員（王者を含む）。
- ハンデボーナス（要項4.6）: players シートの rookie 列に印がある1回生に、bonus_rookie_pt（初期値30）を追加ボーナスと一緒に予選終了後に加算する。予選中のレート計算には入らない。
- 個人戦の成績（個人ページと player_stats シート。個人戦を1投ごとに記録した試合だけ）: 平均ブレイク本数（先攻1投目の得点の平均）、平均上がりターン数（50点で取ったセットの自分の投擲数の平均。相手の3ミス失格で取ったセットは除く）、先攻・後攻セット取得率。率はすべて「60%（3/5）」の形で表示。
- 順位: 合計（レート＋ボーナス）→ 最終レート → 試合数。参加条件（15試合・チーム戦5試合）を満たした人の上位8名が「通過圏内」。8位と9位が完全に同じならプレーオフ表示。
