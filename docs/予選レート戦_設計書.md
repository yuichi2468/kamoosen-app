# 鴨王戦 予選レート戦 設計書

2026-11-13 作成 / 2026-11-14 更新（個人選択の廃止、1投ごとのスコア記録と個人の投擲順を追加・実装）

## 1. 前提と方針

大会要項（第2回鴨王戦 個人用）から読み取った予選の条件と、確定した事項は次のとおりです。

- 期間は 11/24(火) 7:00 〜 12/7(月) 21:00 の2週間。20:59までに**開始**した試合は有効で、開始時刻はアプリのログで判定する。
- 形式は「参加者同士が自由に組んで2先（2セット先取）の試合を行い、結果をレートに反映する」フリー対戦制。運営が組み合わせを決めるラウンド制ではない。
- **すべての試合は2チームの対戦で、各チームは1〜4人**（1vs1、2vs2、1vs3、4vs4 など、人数の組み合わせは自由）。
- チームのレートはメンバーの平均で計算し、得た増減を全員にそのまま反映する（要項どおり）。
- 参加条件は最低20試合、うち5試合以上がチーム戦、同一選手との個人戦は3試合まで。
- 期間終了時の「最終レート＋ボーナス」上位8名が順位戦へ進む。
- 前回王者Aは予選免除。予選中は **Aのレートを1800に固定**して対戦に参加する（Aレイドバトル）。
- 前回参加者は 1500＋(前回最終−1500)/4 から開始（1500未満なら1500）。初期レートは運営がスプレッドシートに個別に入力する（未入力は1500）。
- 要項4.6「ハンデボーナス」（1回生は予選終了時にレート+30）は、15章のとおり追加ボーナスと同じ仕組みで予選終了後に加算する（予選中のレート計算には影響させない）。

参考アプリとの違いは、1対1専用だった試合データを「2チーム × 各1〜4人」に広げる点です。アプリ内部では1対1も「1人チーム同士の対戦」として扱い、計算・入力・表示をすべて同じ仕組みで処理します。

参考アプリのページはこちらの環境から取得できなかったため（通信がブロックされました）、画面構成は要項と一般的なレート戦アプリの形から設計しています。参考アプリ固有の画面や項目で残したいものがあれば教えてください。

## 2. レート計算

### 2.1 基本式（要項どおり）

自チームの平均レートを R、相手チームの平均レートを R' とすると、

- 勝ち: +(24 + (R' − R) × 0.06)
- 負け: −(20 + (R − R') × 0.05)

小数第1位を四捨五入して整数にし、その値を**チームの全員に同じだけ**反映します。平均レートは丸めずに使います。

さらに【確定】**勝ちは最低+10、負けは最低−10**とします（2.4）。

### 2.2 計算例

| 対戦 | 平均 | 勝敗 | 勝った側（1人あたり） | 負けた側（1人あたり） |
|---|---|---|---|---|
| 1500 vs 1500 | 1500 / 1500 | 前者勝ち | +24 | −20 |
| (1600, 1400) vs (1500, 1500, 1500) | 1500 / 1500 | 前者勝ち | +24 | −20 |
| 1700 vs (1500, 1450, 1400) | 1700 / 1450 | 1人側勝ち | +10（式では+9） | −10（式では−8） |
| 1700 vs (1500, 1450, 1400) | 1700 / 1450 | 3人側勝ち | +39 | −33 |

### 2.3 人数が非対称な試合（1vs3 など）の扱い【確定: 人数補正なし】

要項どおり「平均で計算し、全員に同額」を人数に関係なく適用します。モルックのチーム戦は人数に関係なく1ターン1投の交互投擲なので、人数よりメンバーの腕前（平均）が勝敗に効き、平均レートで見る方式と合っています。

副作用として、人数の多いチームが勝つとレートの総量が増えます（1vs3 で3人側が勝つと全体で +52）。また、強い人と組んだ弱い人も同額を得ます。予選の通過は相対順位で決まり、全員にチーム戦5試合以上の条件があるので、許容範囲と判断しました。

### 2.4 増減の下限【確定】

- 勝ちの増分は**最低 +10**（式の値が10未満なら+10）
- 負けの減分は**最低 −10**（式の値が10未満の減りなら−10）

式の値が下限に届くのは、勝ちは相手との平均差がおよそ240以上低い相手に勝ったとき、負けはおよそ210以上高い相手に負けたときです。これで「負けてもレートが増える」ことや「勝っても0」はなくなります。

アプリでの計算順は「式で計算 → 四捨五入 → 下限を適用」です。

```
gain = max(10, round(24 + (R' - R) * 0.06))
loss = max(10, round(20 + (R - R') * 0.05))   // 減らす値
```

### 2.5 計算順と再計算

- 試合は**開始時刻順**にレートへ反映する（その試合開始時点のレートで計算する）。
- 入力ミスの修正や試合の取り消しに備え、アプリは「試合ログから毎回全員分を再計算する」方式にする。レートを直接上書きしない。

## 3. Aレイドバトル

- Aのレートは**1800で固定**し、どの試合でも変動しない。
- Aと対戦した側は、Aを1800として2.1の式で通常どおり計算する。勝てば大きく増え、負けると最低10下がる。

| 自分のレート | Aに勝ったとき | Aに負けたとき |
|---|---|---|
| 1400 | +48 | −10（下限） |
| 1500 | +42 | −10（下限） |
| 1600 | +36 | −10 |
| 1700 | +30 | −15 |

- Aがチームに入る場合は、Aを1800として平均に含める。Aと組んだメンバーは通常どおり増減するが、A自身は変動しない。
- 【確定】Aに勝ったときの特典は、この1800固定で計算したレート増分そのものとし、別枠のボーナス点は設けない。したがって順位決定の「追加ボーナス」は予選では常に0になる（運営が手動で付与する場合に備えて列だけ残す）。
- 【確定】Aとの1vs1にも「同一選手との個人戦は3試合まで」の制限を適用する。Aを含むチーム戦には制限を設けない。

## 4. 組み合わせ・試合数・時間の目安

予選は自由対戦制なので、運営が組み合わせやラウンドを決める必要はありません。そのかわりアプリ側で次の支援をします。

- 「対戦できる相手」表示: 同一選手との個人戦（1vs1）が3回に達した相手（Aを含む）を、1vs1の候補から外して表示する。
- 「おすすめの組み合わせ」表示（任意機能）: その場にいる参加者から、チーム平均がなるべく近くなる分け方を提案する。2チームの平均差が小さいほど、どちらが勝っても増減が標準（+24/−20）に近くなる。
- 参加条件の進捗表示: 「総試合数 x/20、うちチーム戦 y/5」を各自のページに出す。

規模の見積もり（40人、全員が最低20試合の場合）:

- 1人20試合 × 40人 = 延べ800人試合。全て1vs1なら約400試合、2vs2中心なら約200試合。
- 2先の1試合は15〜25分程度が目安。2週間（14日）なら1日あたり15〜30試合程度で、自由対戦制で十分こなせる量です。
- 締切直前に駆け込みが集中しやすいので、「1週目終了時点で10試合」などの中間目安を告知することをおすすめします。

## 5. 予選通過の決め方

- 対象者: 参加条件（20試合以上・チーム戦5試合以上）を満たした人。満たさない人は順位表に表示するが通過対象外とする。
- 順位: 最終レート＋追加ボーナスの合計で決定。上位8名が順位戦へ。
- 同点時: 最終レート → 試合数 → プレーオフ（順位戦進出に関係しない場合はくじ引き）。要項どおり。

## 6. アプリ設計

### 6.1 全体構成【確定: 記録はアプリ、データ管理はスプレッドシート】

```
[参加者のスマホ]  アプリ（HTML 1枚。Apps Script から配信。GitHub Pages などにも置ける）
      │  fetch（JSON）
      ▼
[Google Apps Script ウェブアプリ]  受付窓口・レート計算・入力チェック
      │  読み書き
      ▼
[Google スプレッドシート]  players / matches / settings / ranking / log
```

- **アプリ（フロント）**: 参加者が試合の開始・結果を記録し、ランキングや個人ページを見る画面。データは持たず、すべて Apps Script 経由で読み書きする。実装では Apps Script のウェブアプリとして同じ URL から配信する（別サーバー不要）。外部に置く場合は API_URL を設定する。
- **Google Apps Script（GAS）**: スプレッドシートに紐づけたスクリプトを「ウェブアプリ」として公開し、アプリからのリクエストを受ける。サーバー側で次を行う。
  - 試合開始時刻を**サーバーの時計で**記録する（端末の時計を信用しない。締切判定のため）。
  - 入力チェック（締切後の開始、同一相手との1vs1が4回目、同じ人が両チーム、チーム人数1〜4人外など）。
  - 全試合からのレート再計算と、ランキングシートの書き出し。
  - 同時書き込みの排他（LockService）。40人規模なら十分さばける。
- **記録者**: 個人PINも、アプリを開いたときの「自分」の選択も使わない（2026-11-14 決定）。誰でも試合の開始・結果入力ができる。誤入力やいたずらには「操作元の端末をランダムな記号で log シートに記録（個人は特定しない）」「結果がすぐ履歴・ランキングに出る」「運営が無効化・復元できる」で対応する。相手チームによる確認の仕組みは、記録者を特定しないため廃止した。
- **スプレッドシート**: 運営が直接見て、修正できる「正のデータ」。運営は初期レートの入力、試合の取り消し（status を void に変更）、設定変更をシート上で行う。シートを直接編集したあとは、メニューの「レート再計算」を押すとランキングに反映される。

アプリ→GAS の通信は、CORS の事前確認を避けるため POST の Content-Type を text/plain にして JSON を送る（GAS ウェブアプリでよく使う形）。

### 6.2 シート構成

**players シート**（運営が入力）

| 列 | 内容 |
|---|---|
| player_id | 一意のID（例: P01） |
| name | 表示名 |
| initial_rating | 初期レート。運営が個別に入力。空欄なら1500 |
| fixed_rating | 固定レート（Aのみ 1800、他は空欄） |
| active | 参加中なら TRUE |

**matches シート**（アプリが追記。運営は status 列だけ触る）

| 列 | 内容 |
|---|---|
| match_id | 一意のID |
| started_at | 開始時刻（GAS がサーバー時刻で記録） |
| ended_at | 結果入力時刻 |
| team1_ids / team2_ids | 各チームのメンバー（1〜4人、カンマ区切り） |
| team1_legs / team2_legs | 獲得セット数 |
| team1_score / team2_score | 合計得点（記録用） |
| winner | 1 または 2（未入力なら試合中） |
| status | playing / done / void |
| started_by / entered_by | 開始・結果入力をした端末の記号 |
| delta_team1 / delta_team2 | 再計算時に GAS が書き込む増減（確認用、表示のみ） |

**settings シート**（運営が入力）

| キー | 値の例 |
|---|---|
| start_at | 2026-11-24 07:00 |
| end_at | 2026-12-07 21:00（この時刻以降は試合開始不可） |
| result_deadline | 2026-12-07 23:59（結果入力の締切） |
| min_gain / min_loss | 10 / 10 |
| max_singles_vs_same | 3 |
| min_matches / min_team_matches | 20 / 5 |
| qualify_count | 8 |
| admin_key | 運営画面用のパスワード |

**ranking シート**（GAS が再計算のたびに上書き。手で編集しない）

順位、名前、現在レート、ボーナス、合計、試合数、チーム戦数、条件達成、通過圏内。

**bonus シート**（任意。運営が手動で付与する場合のみ）: player_id、点数、理由。

**log シート**（GAS が追記）: 日時、操作、操作者、内容。取り消しや修正の経緯を残す。

### 6.3 処理の流れ

1. **試合開始**: アプリでチーム分けを選び「開始」→ GAS がチェックし、matches に status=playing で1行追加（started_at はサーバー時刻）。
2. **結果入力**: アプリでセット数・得点を入力 → GAS が winner を記録し status=done。
3. **再計算**: 結果入力のたびに GAS が status=done の全試合を started_at 順に計算し、ranking シートと delta 列を更新する。数百試合なので1秒程度で終わる。
4. **運営の修正**: シートで status を void にする、または値を直す → メニュー「レート再計算」。
5. **締切後**: end_at 以降は開始を拒否。result_deadline を過ぎたら結果入力も拒否し、ranking シートが最終結果になる。

### 6.4 画面

1. **ランキング**: 順位、名前、レート、合計、試合数、チーム戦数、条件達成マーク。上位8名ラインを表示。
2. **試合開始**: チーム1・チーム2にそれぞれ1〜4人を選んで「開始」。開始前に「勝った場合 / 負けた場合」の増減見込みを表示する。1vs1の対戦回数上限に達した相手は選べないようにする。
3. **試合中一覧・結果入力**: 進行中の試合を選び、各チームの獲得セット数・得点を入力して確定。
4. **個人ページ**: レート推移グラフ、対戦履歴、相手別の1vs1回数、参加条件の進捗。
5. **運営画面**（admin_key が必要）: 試合の無効化・復元、再計算ボタン。プレイヤー登録や初期レートの入力はスプレッドシートで直接行う。

## 7. 決定事項

1. 対戦は2チーム対戦、各チーム1〜4人。
2. 人数が非対称な試合も人数補正なし（平均で計算し全員に同額）。
3. Aのレートは1800固定で、Aとの試合も通常どおりレート計算する。別枠ボーナスなし。
4. Aとの1vs1にも同一選手3試合までの制限をかける。
5. ハンデ（1回生+30）は予選終了後に加算する（15章）。予選中のレート計算には入れない。
6. 増減の下限は、勝ち最低+10、負け最低−10。
7. 初期レートは運営が players シートに個別入力する（空欄は1500）。
8. 対戦の記録はアプリで行い、データはGoogle スプレッドシートで管理する（Apps Script 経由で連携）。
9. 個人PINは使わない。
10. アプリを開いたときの個人選択（「自分」）は使わない。記録者は特定しない。

## 9. 1投ごとのスコア記録と個人の投擲順（2026-11-14 実装済み）

試合中に1投ずつ得点を入力し、点数計算・勝敗判定・セット数の記録までアプリが自動で行う機能です。結果入力の手間とミスがなくなり、各セットの得点の流れも残せます。

### 9.1 モルックのルールとアプリでの判定

| ルール | アプリの処理 |
|---|---|
| 倒れたピンが1本なら、そのピンの数字が得点。2本以上倒れたら、倒れたセット数が得点 | 得点は現場で数え、1〜12の点数を選んで「確定」で記録する（2026-11-14 決定。ピンを選ぶ方式・複数本選択はやめた） |
| 1本も倒れなければ0点（ミス） | 点数を選ばずに「確定」を押す（2026-11-16 ミスボタンを廃止）。連続ミス数を+1 |
| ファウル（ラインを踏み越す等） | 専用ボタンは置かない（2026-11-14 削除）。必要なら現場判断で「ミス」として記録する |
| ちょうど50点で、そのセット（レッグ）の勝ち | 自動でセット数を+1し、次のセットへ |
| 50点を超えたらバースト（25点に戻る） | 自動で25点にし、画面に「バースト（25点に戻る）」と表示 |
| 3回連続でミスすると失格（2チーム戦では相手の勝ち） | チーム単位で連続ミスを数え、3回目で自動的に相手チームのセット。**相手チームの得点は50点として記録する**（2026-11-14 決定）。**失格したチームの得点は0点にする**（2026-11-14 変更） |
| 得点するとミスの連続は0に戻る | 自動 |
| 2セット先取で試合終了 | 2セット目を取った時点で試合結果を自動登録し、レートを計算 |

連続ミスは**チーム単位**で数えます（同じチームのAさんとBさんが続けてミスしたら2回）。

### 9.2 先攻と投げる順番【2026-11-14 決定・更新】

- チームは交互に投げます。
- 1セット目の先攻は要項どおりじゃんけんで決め、試合開始時にアプリで先攻チームを選びます。
- **2セット目の先攻は、1セット目の後攻チーム**とし、アプリが自動で切り替えます。
- 3セット目（1-1のとき）の先攻は、要項どおり2セット目終了時点の総得点が高いチームが選びます。アプリが総得点を出して「先攻を選ぶチーム」を表示します（同点ならドローショット）。
- 総得点は「各セットの終了時点の得点の合計」とします。相手の3連続ミスで取ったセットは、自分たちの得点を50点として数えます。

#### 個人の投擲順（試合開始時に選べる）

試合開始時に「個人の投擲順を入れる」かどうかを選べるようにします。

| | 入れない | 入れる |
|---|---|---|
| 記録の単位 | チーム単位（誰が投げたかは記録しない） | 1投ごとに投げた人を記録 |
| 画面の「次」表示 | 「次: チーム2」 | 「次: チーム2 江藤さん」 |
| チーム内の順番 | 現場で管理 | アプリが管理（決めた順に自動で回る） |
| 個人成績 | なし | ヒット率・上がり回数などを集計 |

入れる場合の動き:

- **順番の決め方**: 試合開始画面でチームに入れた順がそのまま投擲順になります。各メンバーの横の「↑」で順番を入れ替えられます。
- **回り方**: そのチームの番が来るたびに、1番目 → 2番目 → … → 最後 → 1番目 と回ります。1人チームは毎回同じ人です。人数が違うチーム同士（1vs3 など）でも、チームごとに独立して回ります。
- **セットごとに選び直す**【2026-11-14 決定】: 2セット目・3セット目の開始前に「投擲順の確認」画面を出し、各チームの順番を選び直せます。前のセットの順番が初期値として入っているので、変えないならそのまま「この順で始める」を押すだけです。新しいセットは、そのセットで決めた順の1番目の人から投げます。
- 3セット目は「先攻チームの選択」と「投擲順の確認」を同じ画面で行います。
- **投げた人の決め方**: 投げた人は入力しません。投擲の順番からアプリ（サーバー側でも再計算）が自動で決めるので、入力の手間が増えず、記録の食い違いも起きません。
- **順番を間違えて投げた場合**: その投擲は記録上「本来の順番の人」に付きます。正しく直したいときは「1投戻す」で戻してから入れ直します（セットの途中での順番変更機能は作らない。2026-11-14 決定）。
- **途中で「結果だけ入力」に切り替えた場合**: それまでの投擲は個人成績に入れません（終わっていない試合の成績になるため）。

#### 個人成績（投擲順を入れた試合だけを集計）

| 項目 | 計算 |
|---|---|
| 投擲数 | 記録された投擲の数 |
| ヒット率 | （投擲数 − ミス）÷ 投擲数。画面と player_stats シート（hit_rate 列）に表示 |
| 上がり回数 | 自分の投擲でちょうど50点にした回数 |
| バースト回数 | 自分の投擲で50点を超えて25点に戻った（バーストした）回数 |

試合が終わった時点で player_stats シートに集計し、個人ページに表示します。無効にした試合は集計から外します。

### 9.4 通信と保存の方式

Apps Script は1回の通信に1〜3秒かかるため、1投ごとにサーバーの応答を待つと入力が止まってしまいます。そこで次の方式にします。

1. 点数計算はスマホ側で即座に行い、画面はすぐ更新する（サーバーと同じ計算コードを使う）。
2. 投擲データはスマホ内に保存しつつ、裏で数投ずつまとめてサーバーへ送る。電波が悪くても入力は続けられ、つながったときに送信される。
3. サーバーは受け取った投擲を最初から再計算して検証し、throws シートに保存する。セット数と勝敗もサーバー側で決めるので、スマホの計算がずれていても記録は正しくなる。
4. 2セット先取が決まったら、サーバーが matches シートに結果（セット数・総得点）を書き、レートを再計算する。いまの「結果を確定」と同じ扱い。
5. 1試合を入力できる端末は同時に1台にします（最初に記録を始めた端末）。ほかの端末では観戦表示になり、「記録を引き継ぐ」を押すと交代できます（電池切れ対策）。

### 9.5 データ（throws シートを追加）

試合中の投擲は matches シートの `throws_json` 列（とセットごとの投擲順 `leg_orders`）に保存し、試合が終わった時点で1投1行に展開して throws シートに書き込みます。記録した端末は matches の `scorer` 列と log シートに残ります。

| 列 | 内容 |
|---|---|
| match_id | 試合ID |
| leg | 何セット目か（1〜3） |
| seq | そのセットの中での投擲番号 |
| team | 1 または 2 |
| player_id | 投げた人（個人の投擲順を入れた試合だけ。入れない試合は空欄） |
| pins | （使わない。旧方式の名残で空欄） |
| kind | normal / miss（過去データ互換のため foul も受け付け、0点・ミス1回として数える） |
| points | 得点 |
| score_after | 投擲後のチームの得点（バーストも反映） |
| miss_streak | 投擲後のチームの連続ミス数 |
| event | win（上がり）/ bust（バースト。25点に戻る）/ out（3連続ミスで失格。このとき失格したチームは0点、相手チームの得点を50としてセットを終える）/ 空 |

規模の目安は1セットあたり30〜60投、1試合で80〜150投です。全300試合でも4万行程度で、スプレッドシートで十分扱えます。

matches シートには `scoring`（manual / throws）列を追加し、どちらの方式で記録した試合かを残します。

## 10. 特別賞（2026-11-14 実装済み）

予選の特別賞（横綱賞は 2026-11-14 に廃止し8つ）について、各賞の **1〜3位とその値** をアプリに表示する。値は試合記録から自動で計算し、運営の手作業はルーキーの登録だけにする。

### 10.1 共通ルール【確定】

- **集計の対象:** 結果が登録された有効な試合だけを数える。無効にした試合は除く。
- **チーム戦:** 個人戦と同じく、チームの結果はメンバー全員の結果として数える。たとえば2-0で勝てば、全員に「2タテ1回」がつく。
- **レートの比較:** チーム戦ではチームの平均レートを使う。値は、その試合の直前のレートで計算する（レート計算と同じ考え方）。
- **前回優勝者A（王者）:** 受賞の対象外とする。Aとの試合は、対戦相手の記録としては数える。
- **同じ値のとき:** 同じ順位にする（例: 1位, 1位, 3位）。3位と同じ値の人は全員表示する。
- **表示する時期:** 期間中もリアルタイムで表示する。settings に `awards_visible`（TRUE/FALSE）を設け、FALSE にすると運営以外には隠せる。

### 10.2 各賞の定義【確定】

| 賞 | 値 | 計算方法 | 対象・最低条件 |
|---|---|---|---|
| MVP賞 | 勝率 % | 勝ち ÷ 試合数 | 予選の最低条件（20試合・うちチーム戦5試合）を満たした人。同じ勝率なら勝ち数が多い方が上 |
| ジャイキリ賞 | レート差 | 勝った試合のうち、自分（チーム）のレートが相手より低かった試合の「相手 − 自分」のレート差の最大値 | 全員。Aとの対戦（Aがいる試合）は対象外 |
| カモネギ賞 | レート差 | 負けた試合のうち、自分（チーム）のレートが相手より低かった試合の「相手 − 自分」のレート差の最大値（＝格上に挑んで大差で負けた） | 全員。Aとの対戦（Aがいる試合）は対象外 |
| 平均得点王 | 1セットあたりの平均得点 | 自チームの各セット終了時の得点の合計 ÷ セット数。セットを取ったときは50点、3ミスで失格したセットは0点で数える | 個人戦・チーム戦の両方を含む（チーム戦はチームの得点）。得点が記録された試合（1投ごとの記録、または結果入力で得点合計を入れた試合）だけ。最低条件を満たした人 |
| 連勝王 | 最長連勝数 | 試合開始の時刻順に並べたときの、連続した勝ちの最大数 | 全員。同じ数なら同じ順位 |
| ルーキー賞 | 予選順位 | ランキングの順位 | players シートで1回生に印をつけた人。同じ順位の決め方はランキングと同じ |
| ジェットコースター賞 | レート差 | 予選中の最高レート − 最低レート（初期レートも含む） | 全員（A・レート固定の人は除く） |
| メモリアル賞 | 何戦目か | 大会全体の試合を開始時刻の順に通し番号にして、100戦目・200戦目・300戦目…の試合の勝者 | その試合の勝ったチームの全員。順位ではなく「100戦目: 〇〇・〇〇」の一覧で表示 |

### 10.3 データ

- **players シート:** `rookie` 列（TRUE/空）を追加し、1回生に TRUE を入れる。setup の再実行で列が追加される。
- **awards シート（新規・自動）:** 再計算のたびに書き直す。列は `award, rank, player_id, name, value, detail, updated_at`。
  - `detail` には、どの試合で出た値かを入れる（例: 「11/25 vs 王者 2-1」）。
- **settings シート:** `awards_visible`（初期値 TRUE）と、メモリアル賞の区切り `memorial_step`（初期値 100）を追加する。
- **計算のタイミング:** レートの再計算（recalc）と同時に、試合記録から全部計算し直す。新しい記録は増やさない。

### 10.4 画面

- **「特別賞」タブを置く**（2026-11-14 変更。タブは ランキング／試合／履歴／個人／特別賞。運営タブは廃止し、ページ右上の小さな「運営」ボタンから開く）。
  - 賞ごとに、賞の名前と定義の短い説明を1行で出し、1〜3位の名前と値を並べる（例: 「ジャイキリ賞　1位 江藤 +276（vs 王者）」）。
  - 該当者がいない賞は「まだいません」と出す。
- **メモリアル賞:** 達成した区切りの一覧を出す。
- **個人ページ:** その人が入っている賞と順位をバッジで出す（例: 「連勝王 2位」）。

### 10.5 決定事項（2026-11-14）

1. **カモネギ賞:** 格上に挑んで、大きなレート差で負けた人が対象。
2. **最低試合数:** MVP賞と平均得点王の最低試合数は、予選の最低条件（20試合・うちチーム戦5試合）と同じにする。
3. **ルーキーの判定:** players シートの `rookie` 列に、運営が1回生の印を入力する。
4. **メモリアル賞の「通算」:** 大会全体の通し番号で数える。
5. **前回優勝者A:** 特別賞の対象外にする。ジャイキリ賞・カモネギ賞（レート差の賞）では、Aとの対戦そのものを数えない。
6. **平均得点王:** 個人戦とチーム戦の両方を含める。チーム戦はチームの得点で数える。
7. **連勝王:** 同じ連勝数なら同じ順位にする。
8. **メモリアル賞:** 次の区切りまでの「あと◯試合」は表示しない。
9. **3ミス失格の得点（全体のルール）:** 3回連続ミスで失格したチームの得点は0点にする。1投ごとの記録・総得点・平均得点王すべてに適用する（アプリには 2026-11-14 に反映済み）。
10. **横綱賞は廃止**（2026-11-14）。
11. **最低条件のある賞（MVP賞・平均得点王・ルーキー賞）は暫定順位も出す:** 最低条件を満たした人を先に並べ、まだ満たしていない人も値の順に続けて「暫定（最低条件 未達）」の印をつけて表示する。最低条件を満たした人の順位が正式な順位になる。
12. **レート差の賞（ジャイキリ賞・カモネギ賞）は試合当時のレートも出す:** 例「11/25 vs 上野・江藤 2-0（当時のレート・チーム平均 1500 vs 1512.5）」。個人戦は本人のレート、チーム戦はチームの平均レート。

### 10.6 社交王・開拓王の追加（2026-11-14 実装済み）

| 賞 | 値 | 計算方法 | 対象 |
|---|---|---|---|
| 社交王 | 組んだ人数 | チーム戦で同じチームになったことのある人の数（同じ人と何度組んでも1人と数える） | 全員（王者は対象外） |
| 開拓王 | 対戦した人数 | 個人戦（1対1）で対戦したことのある相手の数（同じ相手と何度戦っても1人） | 全員（王者は対象外） |

- 共通ルールは他の賞と同じにする。無効試合は数えず、3位まで表示し、同じ値は同じ順位にする。
- 最低条件はつけない。
- 王者と組んだこと、王者と対戦したことも1人として数える【確定】。

## 11. 追加ボーナス（2026-11-14 実装済み）

予選期間中の対戦を盛り上げるため、条件を達成した人に予選終了後、ボーナスをレートに加算する。他の参加者との比較ではなく、条件を達成すれば誰でももらえる。**もらえるのは到達した区分のポイントだけで、区分ごとの合計ではない**（例: 25勝なら +20pt。+10pt と +20pt の合計の +30pt ではない）。

### 11.1 区分

| 項目 | 数え方 | もらえるポイント（到達した区分のみ） |
|---|---|---|
| 勝利数 | 有効な試合の勝ち数（個人戦・チーム戦の両方） | 10勝 +10、20勝 +20、30勝 +30、以降も10勝ごとに +10（40勝 +40、50勝 +50…）。式にすると「10勝ごとの区分数 × 10pt」 |
| チーム戦で組んだ人数 | 社交王と同じ人数 | 5人 +5、10人 +15、20人 +30、30人 +45、全員 +100 |
| 個人戦で戦った相手の人数 | 開拓王と同じ人数 | 5人 +5、10人 +15、20人 +35、30人 +55、全員 +100 |

- 3項目はそれぞれ別に計算し、合計した値をその人の追加ボーナスにする。
  - 例: 23勝・組んだ12人・戦った7人なら、+20 ＋ +15 ＋ +5 で +40pt。
- 「全員」は、自分以外の参加者全員と組んだ（対戦した）場合。人数は players シートで参加中（active）の人で数え、王者も含める【確定】。
- 王者（レート固定の人）は、ボーナスの対象外。

### 11.2 反映のしかた

- 区分の値は settings シートに置き、運営が変えられるようにする（例: `bonus_wins_step` 10、`bonus_partner_tiers` `5:5,10:15,20:30,30:45,all:100`、`bonus_opponent_tiers` `5:5,10:15,20:35,30:55,all:100`）。
- 追加ボーナスは試合記録から自動で計算する。今ある手動の `bonus` シートとは別に足し合わせ、ランキングの「合計（レート＋ボーナス）」に入れる。
- **予選中:** 個人ページに、3項目それぞれの今の数、獲得見込みのポイント、次の区分まであと何勝（何人）かを表示する。ランキングには、まだ加算しない。
- **予選終了後:** 結果入力の締切（result_deadline）を過ぎたら、自動でランキングの合計に加算する【確定】。予選通過（上位8名）もボーナス加算後の合計で決める【確定】。ランキングの表に「ボーナス」列を出し、内訳は個人ページで見られるようにする。

## 12. 個人成績の追加項目（個人戦限定）（2026-11-14 実装済み）

個人ページの「投擲成績」に、次の4項目を追加する。いったん **個人戦（1対1）で、1投ごとに記録した試合だけ** を集計する。チーム戦と、結果だけ入力の試合は数えない。無効にした試合も数えない。

### 12.1 項目と計算方法

| 項目 | 計算方法 | 例 |
|---|---|---|
| 平均ブレイク本数 | 自分が先攻のセットの、1投目の得点の平均。1投目がミスなら0点として平均に入れる | 先攻セットが4つで、1投目が 6・3・0・8 なら 4.25 |
| 平均上がりターン数 | 自分が50点ちょうどで取ったセットで、そのセットに自分が投げた回数の平均 | 9投目で上がったセットと11投目で上がったセットなら 10.0 |
| 先攻セット取得率 | 自分が先攻だったセットのうち、取ったセットの割合（%） | 先攻5セット中3セット取得なら 60% |
| 後攻セット取得率 | 自分が後攻だったセットのうち、取ったセットの割合（%） | 後攻4セット中1セット取得なら 25% |

- 先攻・後攻は、セットごとに実際に先に投げた方で決める。1セット目はじゃんけん、2セット目は1セット目の後攻、3セット目は選んだ方。
- 相手の3ミス失格で取ったセットも「取ったセット」に数える。ただし、平均上がりターン数には入れない（50点まで投げていないため）【確定】。
- 平均ブレイク本数は、記録している得点で計算する【確定】。1本だけ倒したときはピンの数字、2本以上ならその本数が得点になる。

### 12.2 表示とデータ

- **個人ページ:** 「投擲成績」カードの下に「個人戦の成績」を足し、4項目と元になった数（例: 「先攻 3/5セット」）を表示する。個人戦を1投ごとに記録した試合がまだない人には「まだ記録がありません」と出す。
- **player_stats シート:** 列を追加する。
  - break_avg、break_sets（平均ブレイク本数と、元になった先攻セット数）
  - finish_turns_avg、finish_sets（平均上がりターン数と、元になったセット数）
  - first_sets、first_won、first_rate（先攻セット数・取得数・取得率）
  - second_sets、second_won、second_rate（後攻セット数・取得数・取得率）
- 計算は、throws シートと matches シートの記録から再計算のたびに行う。新しく入力する項目はない。

### 12.3 決定事項（2026-11-14）

1. **平均ブレイク本数:** 先攻1投目の **得点** の平均で計算する。入力画面は今のまま。
2. **平均上がりターン数:** 相手の3ミス失格で取ったセットは入れない。先攻・後攻セット取得率では「取ったセット」として数える。

### 12.4 率の表示のしかた【確定 2026-11-14】

率の成績は、すべて「割合（%）＋ 〇/〇」の形で表示する。分母と分子の元の数がわかるようにするため。

| 項目 | 表示の例 | 分子 / 分母 |
|---|---|---|
| ヒット率（既存） | 80%（4/5） | ミス以外の投擲数 / 投擲数 |
| 先攻セット取得率 | 60%（3/5） | 先攻で取ったセット数 / 先攻だったセット数 |
| 後攻セット取得率 | 25%（1/4） | 後攻で取ったセット数 / 後攻だったセット数 |
| MVP賞の勝率（特別賞） | 75%（3/4） | 勝ち数 / 試合数 |

- 平均の成績（平均ブレイク本数・平均上がりターン数・平均得点王）は率ではないので、今までどおり、元になった数を小さく添える（例: 「4.25（先攻4セット）」）。
- player_stats シートには、分子と分母の列（hits と throws、first_won と first_sets など）を率の列と並べて出す。ヒット率のために hits 列を足す。
- 既存のヒット率の表示も、この形に変える（2026-11-14 実装済み）。

## 17. 投擲履歴のスコア表（2026-11-15 実装済み）

試合中と試合終了時の投擲履歴を、今の文字の一覧（「1セット目 チーム1 ○○：12点 → 24」）から、ターンごとのスコア表に変える。対象は1投ごとに記録する試合だけ（結果だけ入力の試合には表がない）。

### 17.1 表の形

| ターン | チーム1（得点・合計） | チーム2（得点・合計） |
|---|---|---|

- 1行が1ターン。両チームが1回ずつ投げたら次の行に進む。セットの先攻チームを左の列にする。
- 見出しはチーム名（メンバーの名前を「・」でつなぐ。個人戦は名前だけ）。次に投げるチームの見出しに ▼ をつける。
- **得点:** 倒した点数。ミスは「-」。
- **合計:** その投擲のあとの合計点。大きな太字。
- チーム戦で投擲順を入れている試合は、得点の下に投げた人の名前を小さく出す【確定】。
- 行は1行おきに薄い灰色にする。まだ投げていないマスは空欄。

### 17.2 合計マスの色

| 状態 | 色 |
|---|---|
| ふつう | 青 |
| 1ミス目（連続ミス1回） | 黄 |
| 2ミス連続（あと1回で失格） | 赤 |
| 3ミス失格 | 濃い赤で「失格」と出し、合計は 0 |
| バースト（50を超えて25に戻る） | オレンジで、合計25の横に小さく「B」 |
| 上がり（50ちょうど） | 緑 |

表の下に、色の意味を1行で出す（例: 「青 ふつう／黄 1ミス／赤 2ミス連続／橙 バースト／緑 上がり」）。

### 17.3 どこに出すか

- **試合中（得点入力の画面）:** 今の文字の一覧の場所（入力ボタンの下）に表を出す。入力ボタンが1画面に収まる今の配置は変えない。
  - 表の上に「1セット目／2セット目／3セット目」の切り替えを置き、最初は今のセットを表示する。終わったセットには「11-50」のようにセットの結果を添える。
  - 表は新しいターンが下に増える。投げるたびに、表の最後の行が見える位置までスクロールする。
- **試合終了（確定待ちの画面）:** 「チーム1の勝ち（2-1）」の下に、全セットの表を上から順に並べる。確定前に見直して、間違いがあれば「1投戻す」で直せる。
- **履歴タブ:** 1投ごとに記録した試合に「スコア表」ボタンをつけ、押すとその試合の全セットの表を開く【確定】。投擲データはボタンを押したときにだけ読み込む（画面を開くたびに全試合分は送らない）。

### 17.4 データ

- 表は、今ある1投ごとの記録（端末の記録と throws シート）から作る。新しく入力する項目も、シートの列の追加もない。
- 履歴タブで見る場合は、サーバーに「この試合の投擲」を返す読み取り用の呼び出しを1つ足す（書き込みはない）。

### 17.5 決定事項（2026-11-15）

2. 今の文字の一覧はなくし、表だけにする。
3. チーム戦では、得点の下に投げた人の名前を小さく出す。

### 17.6 実装メモ（2026-11-15）

- 終わったセットの見出しの点数（例: 「2セット目（50-0）」）は、表の左（先攻）チームから順に書く。凡例の先頭に「左の列が先攻」と出す。
- 試合中の表は高さを約5行分にして、表の中だけスクロールする（入力ボタンが動かないように）。投げるたびに最新の行が見える位置へ自動でスクロールする。

### 17.8 直近の試合からスコア表を開く（2026-11-15 実装済み）

- 個人ページ「直近の試合」で、1投ごとに記録した試合の行に「スコア表 ›」を出す。結果だけ入力の試合には出さない。
- 押すと **スコア表の画面に切り替わる**（タブの中身が入れ替わる。別のページは開かない）。
  - 画面の上: 「‹ 戻る」ボタン、試合の日時、両チームの名前、セット数（例: 2-1）、そのチームのレート増減。
  - その下に全セットのスコア表（17.1・17.2と同じ形と色）。いちばん下にも「‹ 戻る」を置く。
  - 読み込み中は「読み込み中…」を出す。読み込みは押したときだけで、一度読み込んだ試合は覚えておく（もう一度開いても読み込み直さない）。

- **履歴タブも同じ画面にそろえる**【確定】。今の「▼ スコア表」（行の下に開く）を「スコア表 ›」に変え、同じスコア表の画面に切り替えて、戻るで履歴タブの元の位置に戻る。

## 18. 対戦履歴の変動前後のレート・試合開始の2画面化（2026-11-15 実装済み）

### 18.1 対戦履歴: 変動値に加えて変動前後のレートを出す

- 履歴タブの各試合で、今の「+24」の下に、メンバーごとの変動前後を小さく出す。
  - 例（個人戦）: 「工藤 +24」の下に「1524 → 1548」
  - 例（チーム戦）: 「加藤・大西 +24」の下に「加藤 1525 → 1549」「大西 1500 → 1524」を1人1行【確定】。チーム戦は増減は全員同じだが、変動前のレートは人によって違うため。
  - レート固定の人（王者）は「王者 1800（固定）」と出す。
- スコア表の画面の上の試合情報にも、同じ形で出す【確定】。
- 無効にした試合は今までどおり「無効」とだけ出し、レートは出さない。
- データは今ある試合ごとのレート履歴（history の「試合後レート」と増減）から計算する。変動前 ＝ 試合後 − 増減。新しいデータやシートの変更はない。

### 18.2 試合タブ: メンバー選択 → 次の画面で投擲順と先攻後攻

試合の開始を2つの画面に分ける。

**画面1: メンバーを選ぶ**
- 今の「試合を始める」と同じ。名前の横の「1」「2」でチームに入れ、平均レートと勝ったときの増減の見込みを出す。

**画面2: 投擲順と先攻後攻を決める**
