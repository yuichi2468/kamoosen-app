# 鴨王戦 日程調整機能 設計書

2026-11-20 作成 / 同日更新（仕様メモ SPEC.md の内容を反映、実装）

## 1. 目的と方針

予選（11/24〜12/7）はフリー対戦制なので、「いつ、誰が、どこで対戦できるか」が分からないと試合が組めません。そこで、**1時間ごとの時間割に「この時間なら対戦できる」を登録し、みんなで見られる機能**を作ります。いちばんの使いみちは「いま対戦できる人がいるか」を遠隔で確かめることです。

参考にした「日程調整アプリ（引き渡し用）」の README の機能をもとに、次の方針で設計します。

- 【確定 2026-11-20】**既存の対戦記録アプリに「日程」タブとして組み込む**（別アプリにしない）。
  - 保存先は Supabase ではなく、**今のスプレッドシートに `schedule` シートを足す**。読み書きは今と同じ Apps Script（GAS）経由。
  - 選手の一覧は players シートをそのまま使う（別アプリから借りる必要がなくなる）。
  - 期間は settings シートの `start_at` / `end_at` をそのまま使う。順位戦で使うときもこの値を書き換えるだけ。
  - main に入れれば今の自動反映（テスト → GAS 反映 → GitHub Pages 公開）で出る。URL も1つのまま。
- 参考アプリの機能（マスのタップ、なぞって範囲選択、編集、まとめて追加、新着、絞り込み）と仕様メモ（SPEC.md）の決まりは**すべて残す**。
- 日程は「いつ参加できるか」の掲示だけを担う。集まったあとの連絡は LINE、試合の記録は今の試合タブで行う。別の予定（授業など）や、対戦の成立・承認は扱わない。
- 考え方は「1時間ごとの掲示板（例: 11/24 18:00〜19:00）に参加する」。1人が同じ時間に参加できるのは1回だけ。
- 組み込むことで増やせること: 日程のマスから**その人たちで試合開始の画面を開く**、試合中の人を時間割に出す、など（8章）。

### 1.1 別アプリ（参考アプリをそのまま使う）との比較

| | 組み込み（この案） | 別アプリ（Supabase） |
|---|---|---|
| URL | 1つ（今のアプリのタブ） | 2つ（リンクで行き来） |
| 保存先 | 今のスプレッドシート。運営がシートで直接見て直せる | Supabase。運営は SQL か管理画面で操作 |
| 準備 | なし（setup をもう一度実行するだけ） | Supabase のプロジェクト作成、キーの設定 |
| 止まる心配 | なし | 無料プランは1週間使わないと一時停止 |
| 反応の速さ | 書き込みに1〜2秒（GAS の速さ。今の試合記録と同じ） | 速い（0.3秒ほど） |
| 試合との連携 | 試合開始の画面を、メンバー入りで直接開ける | トップを開くだけ |

反応の速さだけは別アプリに劣りますが、登録は1日に数回の操作なので、今の試合記録と同じ「送信中…」の表示で足りると判断しました。

## 2. 用語

- **マス（時間枠）**: 「日付 × 時間帯（1時間）」の1マス。例: 11/24(火) 18時台 ＝ 18:00〜18:59。
- **参加**: ある人が、あるマスに「この時間なら対戦できる」と登録したもの。**1人1マスにつき1件**。
- **自分**: この端末で日程タブを使う人。日程タブを最初に開いたときに名前を選び、端末に覚えておく（3.4）。

## 3. 画面

タブは「ランキング／試合／履歴／個人／特別賞」の右に **「日程」** を足して6つにする。

### 3.1 日程タブの全体

上から順に（仕様メモどおり**時間割1画面が中心**。見た目は今のアプリに合わせ、色は白・黒・グレーと緑1色に抑え、文言は短くする）:

1. **自分の名前**（「自分: 山田 ▾」）。タップで切り替え。
2. **絞り込み**: 希望場所（すべて／高原／鴨川南／飛鳥井／その他。ある場所を選ぶと、その場所を選んだ人と「どこでも」の人を数える）、希望形式（すべて／個人戦／チーム戦。個人戦を選ぶと「個人戦」と「どちらでも」の人を数える）、「自分のみ」。マスの数字が変わる。
3. **新着 N件**（4章）。タップで、その最初のマスへ移動。
4. **時間割**（3.2）。
5. いちばん下に **「まとめて追加」** ボタン（3.5）。

### 3.2 時間割

- 縦が時間帯（7時台〜20時台の14行）、横が日付。**スマホは3日分、広い画面は7日分**を表示し、「‹ ›」で日をずらす（期間は14日）。最初は今日が左端。
- マスの中は**数字だけ**（参加者数）。人数が多いほど濃い緑（0は白、1は薄い、2人以上でしっかり色）。2人以上いれば対戦できる、が一目で分かるようにする。
- **自分が参加しているマス**は枠を太くする。
- 新着のあるマスは右上に**黒い点**。
- **過ぎたマス**は灰色にし、参加・編集はできない（見るだけ）。いまのマスは「いま」と強調。
- 期間外の日は出さない。土日は日付の色を変える。
- 【確定・案B】試合中の人がいるマスは、人数の横に小さく「試合中1」と出す（matches の playing から、いまのマスだけ）。

### 3.3 マスをタップしたとき（詳細）

画面の下からシートを出す。

- 見出し: 「11/24(火) 18時台」
- **参加者の一覧**: 名前とレート。その下に、**指定のある項目だけ**を見出し付きの枠で出す（希望場所・希望形式・ひとこと）。「どこでも」「どちらでも」のままなら何も出さない。新着の人は名前の前に緑の「新」（4章）。自分は先頭。
  - 試合中の人には「試合中」。
- ボタン:
  - 自分が未参加なら **「参加する」** → 入力画面（3.4）が、このマスだけを選んだ状態で開く。
  - 参加済みなら **「編集」**（3.4）と **「参加をやめる」**（このマスだけ取り消す）。
  - 【確定・案A】参加者が2人以上いれば **「このメンバーで試合を始める」** → 試合タブのメンバー選択（設計書 19章の画面1）を開く。チーム分けは自分で行う（2人ならそのまま1vs1で入れる）。
- 詳細を開くと、そのマスの新着は「見た」扱いになる（この画面の「新」は、開いたこのときだけ出る）。

### 3.4 参加の入力画面

| 項目 | 入力 | 既定値 |
|---|---|---|
| 日付 | 選んだ日（変えられない） | タップしたマスの日 |
| 時間 | 「18時台 〜 20時台」を2つの選択で | タップ・なぞったマスの範囲 |
| 希望場所 | 複数選択（3.4.1） | どこでも |
| 希望形式 | 個人戦／チーム戦／どちらでも | どちらでも |
| ひとこと | 文字（100字まで）。任意 | 空 |

- **前回の選択は引き継がない**（毎回、どこでも・どちらでもから始める）【確定】。編集のときは、そのまとまりの今の内容で開く。

- 「参加する」を押すと、範囲の各マスに1件ずつ参加を登録する。**すでに参加しているマスは、新しい内容で上書き**（2件にはならない）。
- 「編集」で開いたときは、**同じ日で、続いていて、内容が同じマスをひとまとまり**として開く（例: 18〜20時台）。範囲を狭めると、外れたマスの参加は取り消す。
- 押したら「送信中…」を出し、終わったら時間割を描き直す（今の試合記録と同じ出し方）。

#### 3.4.1 希望場所の選び方【確定 2026-11-20】

- 選択肢は **高原／鴨川南／飛鳥井／どこでも／その他（自由入力）** のボタン。
- **複数選べる**（例: 高原と飛鳥井）。「その他」を選ぶと文字の入力欄が出る（20字まで）。「その他」と高原などを一緒に選ぶこともできる。
- **「どこでも」は他と同時に選べない**。「どこでも」を押すと他の選択が外れ、他を押すと「どこでも」が外れる。
- **何も選ばなければ「どこでも」**として登録する。
- 一覧での出し方: 「高原・飛鳥井」「その他: ◯◯」「どこでも」。

**自分の選び方**: 日程タブを初めて開いたとき、選手一覧から自分の名前を選ぶ（端末に覚えておく。ほかのタブには影響しない）。設計書 6.1 の「自分の選択は使わない」は試合記録の話で、日程は「誰が来るか」が本体なので、ここだけ例外とする。

### 3.5 まとめて追加

- **日**: 「平日」「土日」「すべて」のボタン＋日付ごとのボタン（14日分を**7列×2行**）。過ぎた日は選べない。
- **時間帯**: 開始と終了（例: 18時台〜20時台）。
- 希望場所・希望形式・ひとことは 3.4 と同じ。
- **既定では、参加済みの時間は飛ばす**（今の内容のまま）。「参加済みの時間も上書きする」にチェックすると上書きする。
- 「◯日 × ◯時間 ＝ ◯マスに参加します（参加済み◯マスは飛ばします）」と件数を出してから確定。1回で200マスまで。

### 3.6 なぞって範囲選択

- パソコン: マスを押したままなぞる。
- スマホ: **長押し（0.4秒）してから**なぞる。ふつうのスワイプは時間割のスクロールにする。
- 範囲は**同じ日の縦方向だけ**（ほかの日にまたがる選択は「まとめて追加」で行う）。指を離すと 3.4 がその範囲で開く。
- 参考アプリでは実機で確かめていない操作なので、実装後にスマホ実機で確認する。うまく動かない端末向けに、3.4 の時間の選択だけでも範囲は入れられるようにしておく。

## 4. 新着の出し方

【確定 2026-11-20（仕様メモどおり）】

- 新着は、**前回この画面を閉じたあとに、自分以外の人が新しく参加した、自分が参加している時間のもの**だけ。内容の編集は新着にしない（`created_at` で判定）。
- 「新着 N件」（参加の件数）と、マスの右上の黒い点で示す。
- マスの詳細を開くと、その時間の分は「見た」扱いになり、新着から外れる。開いた画面では、そのときだけ名前の前に緑の「新」を付ける。
- 「見た」記録と「前回閉じた時刻」は端末ごとに保存する（日程タブから離れたとき・アプリを閉じたときを「閉じた」とする）。
- 通知（LINE など）は送らない。集まったあとの連絡は LINE で行う。

## 5. データ

### 5.1 schedule シート（新規。アプリが書き込む）

| 列 | 内容 |
|---|---|
| player_id | 選手（players の player_id） |
| date | 日付（yyyy-mm-dd） |
| hour | 時間帯（7〜20。18 は 18:00〜18:59） |
| place | 希望場所。選んだ場所をカンマ区切り（例: `高原,飛鳥井`）。「どこでも」は `any`。「その他」を選んだときは `other` を含む |
| place_other | 「その他」の自由入力（20字まで）。`other` を選んでいないときは空 |
| format | single / team / any |
| comment | ひとこと（100字まで） |
| created_at | 最初に参加した時刻（サーバー時刻） |
| updated_at | 最後に変えた時刻（サーバー時刻。新着の判定に使う） |
| device | 操作した端末の記号（今の試合記録と同じ。個人は特定しない） |

- **player_id・date・hour の組で1行**（1人1マス1件）。同じ組が来たら上書きする。
- **1人あたり400マスまで**。超える登録はサーバーで断る。
- 取り消しは**行を消す**。経緯は log シートに残す（schedJoin / schedLeave と、端末の記号）。
- 量の見込み: 40人 × 平均20マスで800行ほど。最大でも 40 × 14日 × 14時間 ＝ 7,840行で、GAS で十分さばける。

### 5.2 settings シート（追加）

| キー | 値の例 | 内容 |
|---|---|---|
| sched_day_start | 7 | 時間割の最初の時間帯 |
| sched_day_end | 20 | 時間割の最後の時間帯（end_at が 21:00 なので 20時台まで） |
| sched_places | 高原,鴨川南,飛鳥井 | 希望場所の選択肢（カンマ区切り）。「どこでも」「その他」はこの設定に関係なく必ず出す |

期間は `start_at` / `end_at` の日付を使い、新しい設定は増やさない。setup をもう一度実行すると、シートと設定の行が足される（今の仕組みどおり）。

## 6. サーバー（Code.gs）

### 6.1 操作（api の action）

| action | 内容 | 書き込み |
|---|---|---|
| `schedule` | 期間内の全参加を返す（players の名前とあわせて） | なし |
| `schedSet` | `{ player_id, items:[{date,hour}], remove:[{date,hour}], place:[..], place_other, format, comment, skip_existing }` を登録・上書き。編集で外した時間は remove で消す。まとめて追加もこれで送る（skip_existing で参加済みを飛ばす） | あり |
| `schedLeave` | `{ player_id, items:[{date,hour}] }` の参加を消す | あり |

- 書き込みは今と同じく LockService で排他し、まとめて読み書き（1回の setValues）で行う。
- `state`（ランキング等）とは**別の操作**にする。日程を見ない人の通信を増やさないため。
- 入力チェック: 選手が players にいて active、日付が期間内、時間が sched_day_start〜end の範囲、**過ぎたマスは不可**（サーバー時刻で判定。いまのマスは可）、ひとことは100字まで。1回の登録は200マスまで、1人の合計は400マスまで。place は sched_places の場所・`other` の組み合わせか `any` だけ（`any` と他の同時指定は不可、空は `any` にそろえる）。`other` のときは place_other が必須（20字まで）。
- 日程の操作に運営パスワードは使わない。運営画面からの一括削除も作らない（シートで直接消せる）。

### 6.2 画面の更新

- 日程タブを開いたとき・端末に戻ってきたときに `schedule` を読む。
- 日程タブを開いている間は、今の30秒ごとの更新に `schedule` も加える（入力中は書き換えない、も今と同じ）。
- 案B の「試合中」は、`state` に今ある試合中の一覧（matches の playing）を使う。サーバーの追加はない。
