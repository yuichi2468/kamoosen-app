# 鴨王戦 全員のスタッツ一覧シート 設計書

2026-11-27 作成 / 同日更新（2章の5点を確定。「8位との差」の列を追加。実装）

## 1. 目的と方針

運営がスプレッドシートを開いたときに、**全員の勝率・勝利数・試合数・レートなどを1枚の表で見比べられる**ようにします。今は同じ数字がアプリの個人ページに1人ずつ出ているだけで、シートでは `ranking`（順位・レート・試合数）、`player_stats`（投擲成績）、`extra_bonus`（追加ボーナス）、`awards`（特別賞）に分かれていて、勝率や連勝はシートのどこにもありません。

- スプレッドシートに**新しいシート `stats`（全員のスタッツ）を1枚足す**。中身は見るだけの出力で、手で書き換えても次の更新で上書きされる（`ranking` と同じ扱い）。
- 数字は**アプリの個人ページと同じ計算**（`computeRatings`・`computeProfiles`・`computeSinglesStats`・`computeThrowStats`・`computeExtraBonus`）から出す。アプリとシートで数字が食い違わないように、新しい計算は作らない。
- アプリの画面は変えない。今あるシート（`ranking`・`player_stats` など）も今のまま残す（`player_stats` はアプリが投擲成績を読むのに使っているため）。
- main に入れれば、今の自動反映（テスト → GAS 反映 → GitHub Pages 公開）で出る。反映後に setup を1回実行するとシートができる（実行しなくても、次の更新で自動で作る）。

## 3. 表の作り方と更新のタイミング（Q1）

### 3.1 選択肢

- **A. GAS が書き出す【推奨】**: 今の `recalc()`（結果が入るたびに走る再計算）の最後で `stats` シートを丸ごと書き直す。`ranking`・`player_stats` と同じやり方。
  - 更新されるのは、試合の結果が確定したとき（スコア入力・結果だけ入力）、運営画面で試合を取り消し・復元したとき、運営画面かシートのメニューで「レート再計算」を押したとき。
  - シートを直接直した（matches の値や players を変えた）ときは、今と同じく「鴨王戦 > レート再計算」を押すと反映される。
  - 右端に `更新日時` の列を出すので、いつの数字か分かる。
  - 1回の再計算が少し長くなるが、今の再計算はすでに同じ計算（特別賞の集計など）をしているので、増えるのはシートに書き込む時間くらい（40人×45列で1秒未満の見込み）。
- **B. シートの数式**: matches のチーム列はカンマ区切りで、レートは全試合を順に計算しないと出ないので、数式ではレート・連勝・個人戦の成績・ボーナスが作れない。出せるのは試合数と勝利数くらいになり、アプリと数字がずれやすい。
- **C. メニューを押したときだけ**: 毎回の再計算は軽くなるが、押し忘れると古い数字のまま見てしまう。今の再計算は十分速いので、自動にしない理由が小さい。

### 3.2 シートの見た目（A のとき）

- 1行目にグループ名（「基本」「試合」「個人戦の成績」など）、2行目に項目名。3行目から1人1行。
- 1〜2行目と、左の「順位」「名前」の2列を固定（スクロールしても見える）。
- 2行目にフィルタを付ける。運営がフィルタで並べ替え・絞り込みをしても、次の更新で元の並びに戻る（ずっと残したいときはスプレッドシートの「フィルタ表示」を使う。自分だけに効き、更新後も残る）。
- 率は数値（0.583 など）で入れて「58.3%」の表示形式にする。並べ替えが正しく効くように、文字の「58.3%（7/12）」にはしない。分母（試合数・投擲数など）は隣の列に出す。
- 記録がない項目は空欄（0 と区別するため）。

## 5. 鴨王（レート固定の人）の扱い（Q3）

鴨王は予選の順位の対象外だが、試合数や勝率は他の人と同じく数えられるので、運営が見比べられるほうが便利。【推奨】**A**。

- **A. 同じ表のいちばん下に載せる【推奨】**
  - 順位の列は「王者」。合計・8位との差・ボーナス・通過圏は空欄（公式の順位に入らないため）。最低条件の列には参考合計の最低試合数の進み具合を「（参考合計）あと3試合」「（参考合計）達成」の形で出す。
  - レートは固定値（1800）。開始レート・最高・最低・増減は空欄。
  - 「参考レート」「参考合計」の列に数字を入れる（並べ替えができるように数字のまま。暫定かどうかは最低条件の列で分かる）。ボーナスの内訳は他の人と同じく出す（参考合計に入っている分）。
  - 試合・個人戦の成績・投擲成績は他の人と同じ。
  - 運営画面で参考レートを「表示しない」にしていても、シートには出す（シートは運営しか見ないため。今の awards シートと同じ考え方）。
- **B. 載せない**: 表がすっきりするが、鴨王の成績はアプリでしか見られない。
- **C. 載せるが参考レートは出さない**: 参考レートの表示設定と揃えたい場合。

## 6. 行の並びと見出し（Q4・Q5）

### 6.1 行の並び（Q4）

- **A. ランキング順【推奨】**: ranking シートと同じ並び（合計 → レート → 試合数 → 名前）。その下に鴨王、そのまた下に不参加（players の active が FALSE）で試合の記録がある人。試合が1つもない不参加の人は載せない。
- **B. 名前順**: 人を探しやすいが、順位を見るには並べ替えが要る。A でも名前の列で絞り込めば探せる。

### 6.2 見出しの言葉（Q5）

- **A. 日本語【推奨】**: このシートはアプリが読み込まない、人が見るためだけの表なので、「勝率」「個人戦の勝率」のように日本語にする。シート名は他と揃えて `stats`。
- **B. 英語**: ほかのシート（`player_stats` の `hit_rate` など）と揃う。数式やほかのツールで読むときは扱いやすいが、運営が見るには分かりにくい。

## 7. 実装（2026-11-27）

- `Code.gs`
  - `SHEET.stats = 'stats'` を足す。見出しは `HEADERS.stats` に2段（グループ名・項目名）で持つ。
  - 1人1行のデータを作る純粋な関数 `buildStatsRows(players, matches, res, ranking, extra, bonus, throwStats, cfg)` を作る（シートに依存しないのでテストできる）。中で `computeProfiles`・`computeSinglesStats` を呼ぶ。最高・最低レートは `res.history` から出す。
  - `recalc()` の最後で `stats` シートを書き直す（`clearContents` → 値を書く → 率の列に `0.0%` の表示形式 → 1〜2行目と左2列を固定 → フィルタを付け直す）。シートがなければ作る。
  - `setup()` の見出しを入れる処理からは外し、最後の `recalc()` で作る（見出しが2段で、毎回丸ごと書き直すため）。
  - 表示形式・固定・フィルタの設定に失敗しても、再計算そのものは止めない。
- テスト（`test/test.js`）
  - `buildStatsRows` で、勝率・個人戦とチーム戦の勝率・連勝・最高最低レート・最低条件の文言が個人ページの数字と一致すること、鴨王の行（順位「王者」、参考レートの列）、不参加の人の扱い、記録がない項目が空欄になること。
  - `recalc()` を通して `stats` シートが書かれること（gas-mock）。
- README のシート一覧に `stats` を足す。
- アプリ（index.html）は変更なし。
