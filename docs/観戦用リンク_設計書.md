# 鴨王戦 観戦用リンク 設計書

2026-11-27 作成 / 同日更新（2章の4点を推奨どおりに確定、実装。9章: 試合タブへのまとめ・ルールタブ）

## 1. 目的と方針

鴨王戦に参加していない人（他の部員、OB・OG、家族など）にも、**いまの順位や試合の様子**を見てもらえるようにします。参加者用のアプリとは別に、**見るだけの「観戦用リンク」**を1つ作って配ります。

- 依頼どおり、**「試合」タブと「日程」タブは出さない**。試合の開始・記録・取り消し、日程の登録はできない。
- **「運営」ボタンも出さない**。
- 見られるのは「ランキング／履歴／個人／特別賞」（3章）。試合中の試合を見せるかは 4章で決める。
- 新しく別のアプリは作らない。**今の index.html を「見るだけモード」で開く**形にする（画面の作りや計算は参加者用と同じなので、直したところが両方にすぐ反映される）。
- サーバー（GAS）とスプレッドシートには**手を入れない**のが基本（読み取りの API `state`・`matchThrows`・`watch` は今あるものをそのまま使う）。
- main に入れれば、今の自動反映（テスト → GAS 反映 → GitHub Pages 公開）で出る。

### 1.1 用語

- **参加者用アプリ**: 今配っている URL（`https://yuichi2468.github.io/kamoosen-app/`）。今までと何も変わらない。
- **観戦用リンク（観戦ページ）**: 今回作る、見るだけの URL。
- **観戦画面**: 第21章（予選レート戦 設計書）で作った、試合中の試合のスコア表を約5秒ごとに更新して見る画面。名前が似ているので、この設計書では「試合の観戦画面」と書く。

## 3. 観戦ページの画面

### 3.1 見出し

- タイトルは「鴨王戦 予選（観戦用）」。ヘッダーの期間表示（「期間 11/24 〜 12/7（残り N日）」）はそのまま出す。
- ヘッダーの右は **「↻ 更新」だけ**（「運営」ボタンは出さない）。
- タブの上に細い帯で「観戦用のページです（見るだけ）」と出す。参加者がうっかり観戦ページを開いて「試合が始められない」と迷わないように、帯に「記録は参加者用のアプリで」と添える。

### 3.2 タブ

| タブ | 観戦ページ | 中身 |
|---|---|---|
| ランキング | 出す | 参加者用と同じ（太線・通過圏の色・レイドバトル） |
| 試合中 | **Q1 で決める** | 4章 |
| 試合 | 出さない | |
| 履歴 | 出す | 参加者用と同じ。試合をタップするとスコア表（`matchThrows`。読み取りのみ） |
| 個人 | 出す | 参加者用と同じ（選手を選ぶ・レート推移・投擲成績など） |
| 特別賞 | 出す | 参加者用と同じ。運営が特別賞を非表示にしているときは「現在表示されていません」 |
| 日程 | 出さない | 運営画面の「日程タブを表示」の設定にかかわらず出さない |

- 並びは「ランキング／試合中／履歴／個人／特別賞」（Q1 が A のとき）。最初に開くタブはランキング。
- ランキングの名前をタップすると個人タブに移る、は参加者用と同じ。
- 参考レート（鴨王）の表示など、運営画面の表示設定は参加者用と同じに従う。

### 3.3 出さないもの・押せないもの

- 試合の開始、スコア入力、引き継ぎ、取り消し、結果だけ入力、運営の操作、日程の登録は**画面に出さない**。
- 念のため、画面の中の送信の処理（`act` など）でも、観戦ページでは書き込みの API を呼ばずに止める（何かの拍子にボタンが出ても送られない）。
- この端末に参加者用アプリで記録中の試合が残っていても、観戦ページではスコア入力を開かない（「この端末で記録中」「スコア入力に戻る」も出さない）。
- Q4: 参加者用アプリへのリンクは【確定】置かない。観戦の人が試合を始めてしまう入口を作らないため。参加者は今までどおり参加者用の URL（ホーム画面のアイコン）から開く。

### 3.4 自動更新

- 参加者用と同じく **30秒ごと**にランキングなどを読み直す（画面が裏に回っている間は読まない）。「↻ 更新」でもすぐ読み直せる。
- 試合の観戦画面は今と同じく約5秒ごと（4.2）。

## 4. 試合中の試合を見せるか（Q1）

「いまの状況が分かる」には、いま誰と誰が試合をしているかが一番伝わるので、【確定】**A**。

### 4.1 選択肢

- **A. 「試合中」タブを足す【確定】**: 試合タブの上半分（試合中の一覧）だけを持ってきたタブ。カードをタップすると試合の観戦画面（第21章）が開き、スコア表が約5秒ごとに更新される。
  - 一覧のカードは今と同じ（対戦チーム・開始時刻・今のセットと点数・次に投げる人）。右下は「観戦する ›」。結果だけ入力の試合は「結果だけ入力の試合（スコア表なし）」と出し、タップしても結果入力の欄は出さない。
  - 試合の観戦画面の下の「この試合の操作」（スコア入力を開く・引き継ぐ・取り消す・結果だけ入力に切り替える）は**出さない**。
  - 試合中がないときは「いま試合中の試合はありません」。タブにはいまの試合数を「試合中 2」のように出す。
- **B. ランキングの上に「いま試合中」の欄**: 対戦カードと今の点数を一覧で出すだけ（スコア表は開かない）。タブは増えないが、点数は30秒ごとの更新になる。
- **C. 出さない**: 終わった試合（履歴・ランキング）だけ。いちばん簡単。

### 4.2 サーバーの負担

- 試合の観戦画面は、開いている人1人につき約5秒に1回 `watch`（1試合分を読むだけ）を呼ぶ。ランキングなどの `state` は1人30秒に1回。
- `watch` は matches シートを読むだけで、ロックも書き込みもしないので、記録している端末の送信を待たせない（第21章と同じ）。
- 目安として、観戦の人が20人いても `state` は1秒に1回弱、`watch` は観戦画面を開いている人の数だけ。GAS の同時に動かせる数（30件ほど）の中に収まる見込み。実際に重いと感じたら、観戦ページだけ間隔を延ばす（`state` 60秒、`watch` 10秒）ことで対応する。

## 5. リンクの形（Q2）

### 5.1 選択肢

| | A. 別のページ【確定】 | B. 同じページに印 |
|---|---|---|
| URL | `https://yuichi2468.github.io/kamoosen-app/watch/` | `https://yuichi2468.github.io/kamoosen-app/?view=watch` |
| 作り方 | 公開のときに index.html をもう1つ書き出し、「見るだけ」の印を入れる（中身は同じファイル） | 画面が URL の `?view=watch` を見て見るだけにする |
| ホーム画面に追加したとき | 名前が「鴨王戦（観戦用）」になり、参加者用と区別できる | 参加者用と同じ名前になりやすい |
| URL を少し消すと | `watch/` を消せば参加者用が開く | `?view=watch` を消せば参加者用が開く |
| LINE などで送るとき | 短く、間違えにくい | `?` 以降が落ちると参加者用が開いてしまう |

- どちらも、URL を書き換えれば参加者用アプリにたどり着ける（参加者用の URL はもともと誰でも開ける）。「見せたくないから隠す」のではなく、「見る人が迷わない・誤って押さない」ための分け方と考える。
- A は「?」以降が落ちて参加者用が開いてしまう事故がないので、【確定】**A**。

### 5.2 A の作り方

- index.html の `var API_URL = '';` の下に `var VIEW_ONLY = false;` を1行足す。
- GitHub Pages に公開する手順（`.github/workflows/deploy-gas.yml` の「公開する画面を作る」）で、`site/index.html` に加えて `site/watch/index.html` を書き出す。こちらは `VIEW_ONLY = true` にし、`<title>` を「鴨王戦 予選（観戦用）」にする。
- GAS の URL で直接開いたときは今までどおり参加者用（観戦ページは GitHub Pages だけ）。

## 6. 書き込み（試合の開始など）の保護（Q3）

### 6.1 今の状態

- 今のアプリは、ログインも PIN もなく、**URL を知っている人なら誰でも試合の開始・結果入力・取り消し・日程の登録ができる**作り（README「運営」の項）。運営の操作だけが `admin_key` で守られている。
- 画面（GitHub Pages）の中にはデータの取得先（GAS の URL）が書かれていて、リポジトリも公開。なので、**観戦ページでボタンを隠しても、書き込みそのものを止めることにはならない**（仕組みを知っている人なら直接送れる）。ただしこれは観戦ページを作る前から同じで、観戦ページで新しく危なくなるわけではない。
- いたずらや誤入力には、今と同じく「端末の記号を log シートに残す」「結果がすぐ履歴に出るので気づける」「運営ボタンで無効化・復元」で対応する。

### 6.2 選択肢

- **A. 今回は足さない【確定】**: 観戦ページは画面を分けるだけ。参加者は今の URL のまま、何も変わらない。予選の期間中（〜12/7）に参加者全員へ配り直す手間がない。
  - 観戦ページを配ることで、**参加者用の URL を参加者以外に広めなくてよくなる**ので、むしろ今より安全側になる。
- **B. 参加者用の鍵を足す**: settings シートに `play_key` を足し、試合の開始・記録・取り消し・日程の登録はこの鍵がないと受け付けないようにする。参加者用の URL に鍵を入れる（例: `…/kamoosen-app/#k=xxxx`。一度開けば端末に覚える）。
  - 観戦ページには鍵が入らないので、本当に書き込めなくなる。
  - そのかわり、**参加者全員に新しい URL を配り直す**必要があり、鍵の入っていない古いホーム画面アイコンからは記録できなくなる（試合中に切り替えると記録が送れなくなるおそれ）。鍵が LINE で広まれば効果はなくなる。
  - 入れるなら、順位戦の前など試合のない時期がよい。

## 9. 試合タブへのまとめ・ルールタブ（2026-11-27 実装済み）

### 9.1 ねらい

- 参加していない人にも、鴨王戦がどんなルールで動いているかを分かってもらう（ルールの概要）。モルック自体のルールは書かない（2026-11-27 変更）。
- タブを減らし、試合に関するもの（試合中・終わった試合）を1か所で見られるようにする。

### 9.2 タブ（3.2 を変更）

観戦ページのタブは **「ランキング／試合／個人／特別賞／ルール」** の5つ。

- **試合**: 上に「試合中（N）」のカード（今までの「試合中」タブと同じ。タップで試合の観戦画面）、その下に「対戦履歴」（参加者用の履歴タブと同じ。日ごとに開閉、スコア表）。試合中がないときは「いま試合中の試合はありません。」の1行だけ出して、履歴を続ける。
- 「履歴」タブと「試合中」タブはなくす（試合タブにまとめた）。
- **ルール**: 9.3 の内容。参加者用アプリには出さない。

### 9.3 ルールタブの中身

カードを上から順に並べる。数字は settings シートの値を使い、運営が設定を変えると自動で変わる。

1. **鴨王戦の予選**: 期間、フリー対戦制、合計（レート＋ボーナス）の上位8名（`qualify_count`）が順位戦へ。
2. **試合の形**: 2チームで各1〜4人（`max_team_size`）、個人戦とチーム戦、2セット先取、2・3セット目の先攻、アプリで記録していること。
3. **レートの計算**: 初期値（`initial_rating`）、チーム平均で計算して全員に同じだけ、勝ち・負けの式（`win_base` など）、最低 ±10、例。
4. **予選通過の条件**: 最低15試合・チーム戦5試合（`min_matches`・`min_team_matches`）、同じ相手との個人戦は3試合まで（`max_singles_vs_same`）、順位の決め方。
5. **ボーナス**: 勝利数・組んだ人数・戦った相手の人数の区分（`bonus_*`）、1回生のハンデ（`bonus_rookie_pt`。0 なら出さない）。
6. **鴨王（前回王者）**: 予選免除、レート固定（レイドバトル）、順位対象外。レート固定の人がいないときは出さない。
   - 参考レート（参考レートを表示する設定 `virtual_rating_visible` のときだけ）: ほかの人と同じように変動した場合のレート（初期値は前回のレートから換算した値。`virtual_initial_rating`、空欄なら固定レート）、予選後に参考合計を予選参加者の最終合計と比べ、その順位を順位戦の投げ順などに使うこと、参考合計（参考レート＋ボーナス、`virtual_min_matches` 試合までは暫定）、公式のレート・順位・特別賞には使わないこと、見られる場所、鴨王がほかの人と組んだチームは参考レートで平均を出すこと（予選レート戦 設計書 第20・22・25章）。
7. **特別賞**: 主な賞の名前と、特別賞タブで見られること。

### 9.4 データ

- サーバーの `state` が返す設定に `bonus_wins_step`・`bonus_wins_pt`・`bonus_partner_tiers`・`bonus_opponent_tiers`・`bonus_rookie_pt` を足す（読み取りだけ。ルールタブのボーナスの区分に使う）。
